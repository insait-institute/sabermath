# - roberta/bert/e5 moved from --driver st: run_model.py's old "vector
#   accumulation unsupported by vLLM" restriction is gone (VLLMProcessor now
#   chunk+means client-side, identically to the ST path - Spearman 1.0000).
#   bert additionally needs export_clean (its MLM checkpoint prefixes tensors
#   'bert.', which vLLM's BertModel loader can't strip).
# - jina-v5-text-small is a NEAR-MATCH (Spearman 0.9932) - vLLM's native jina
#   support applies its own retrieval adapter/prompt handling; its published
#   number predates this flip (legacy ST provenance).
# - jina-v5-text-nano MUST stay on st: EuroBERT backbone behind the same
#   jina_embeddings_v5 architecture name; vLLM's implementation assumes the
#   Qwen3 backbone and fails to load it (missing q/k_norm weights). Its line
#   gained default_task=retrieval - current jina remote code refuses to
#   encode without a task at all, so the old kwargs no longer even ran.
#
# - the four reason-embed-*-0928 lines (added 2026-08-28) all carry the same
#   config as the reason-embed-qwen3-8b entry in GENERIC_MODELS over in
#   scripts/run_rerankers.py. The other three are that model's data, size and
#   backbone ablation arms, and only stay comparable if preprocessing is
#   identical; the baseline arm is listed here too so a run_models.sh sweep
#   produces the comparison and not just the arms. Every repo in the family
#   ships modules.json = [Transformer, Pooling(lasttoken)] with
#   similarity_fn_name=cosine, so the LAST+normalize pooler override IS the
#   vendor stack. All four declare torch_dtype float32, and vLLM's "auto"
#   downcasts a float32 POOLING model to fp16, so no dtype pin is needed to
#   keep the arms on one precision. max_model_len on the llama arm only
#   re-imposes the 40960 window its Qwen3 siblings advertise (a Llama-3.1
#   config says 131072, and vLLM sizes a pooling model's profiling run for
#   the whole window, having no chunked prefill for them) - the longest
#   statement-full document is ~6k tokens, so nothing is truncated either
#   way. Read the comment in run_rerankers.py before changing any of this,
#   and change it in both places.
#
# - RTriever-4B (added 2026-08-28) is a Qwen3-Embedding-4B finetune, so it
#   takes the same LAST+normalize pooler as the rest of that family and, like
#   them, runs prompt-free here despite declaring the stock
#   "Instruct: ...\nQuery:" prompt. Its GENERIC_MODELS twin in
#   scripts/run_rerankers.py carries the same config.
#
#   The other models added that day - retro-star-8b/32b and the
#   reason-rewriter + reason-embed composition - are deliberately ABSENT from
#   this file. run_model.py only builds plain HuggingFace embedders, API
#   clients and the lexical baselines; those three need custom processors

#   pipeline) and exist only as run_rerankers.py entries.
